## 4. 見つかった地雷（**本番前に必読**）

### ① `_run_v12_gen.py` に ABLATE を付けて流してはいけない
出力先が `out/dataset_outdoor_siren_v12` 固定で、かつ既存foaをスキップする再開設計。
そのまま流すと **(a) 全部スキップして何も生成されない**（基準が埋まっている場合）か、
**(b) 基準をablation音声で上書きする**（空の場合）。
→ arm専用の `scripts/_run_v12_abl_gen.py` を新設して回避した。

### ② サーバで `git pull` してはいけない
リポジトリは `*.flac` のみ gitignore で、**metadata/masks のCSVは追跡対象**。
サーバ側でこれらは生成物として存在するため、`git pull` は
「ローカルの変更を上書きする」と判断して **abort する**（実際に2026-08-15にabortした）。
→ 新規ファイルは **scp で個別に転送**する。`git checkout -f` や `git pull -f` は
**絶対に使わない**（基準データセットのCSVが消える）。

### ③ 学習sbatchは `server_sde/` にある
`server/` には v11 系しか無い。v12の学習は `server_sde/v12_g45_w3.sbatch`（job315）。
sbatchは `~/research/PSELDNet/PSELDNets` へ cd してそこの `_train_sde12.py` を呼ぶので、
**PSELDNets側の同期が前提**（2026-08-15時点では同期済みを確認）。

### ④ 採点スクリプトも正解の参照先が基準固定（**黙って誤る**ので最も危険）
`_v12_score.py` は `DS12 = out/dataset_outdoor_siren_v12` を正解ラベルの参照先に固定している。
armの予測をそのまま流すと **armの予測を「基準の世界の正解」で採点**してしまう。
破壊はしないが**エラーも出ず誤った数値が出る**ため、地雷①②より発見が遅れる。
→ `scripts/_v12_abl_score.py` を新設し `--gt self|full` で明示切替する:
  - `--gt self` = armの世界の正解（自条件val）
  - `--gt full` = 基準の世界の正解（フル物理val＝**主要評価**）
また `_v12_score.py` / `_e0_probe_score.py` / `_score_sde_dist.py` は**サーバに存在しない**
（ローカルのみ）ので、採点前にscpが必要。

### ⑤ 学習の時間制限（**確認runで実際に切られた**）
a100の `3g.40gb` スライスでは **91.7秒/エポック → 100エポックに約2時間33分**かかる。
pro_6000の実績（46分）で `-t 02:00:00` を申告したところ、**エポック80で TIMEOUT**した。
→ 本番でa100_3gを使うなら **`-t 04:00:00` 以上**を申告する。pro_6000が空いているなら
そちらの方が3倍速い。なお `scontrol update TimeLimit=` による延長は**権限が無く不可**
（`Access/permission denied`）。チェックポイントは毎エポック `last.ckpt` に保存されるので、
切られても `server_sde/abl_infer.sbatch` で推論だけ回収できる。

### ⑥ 生成シャードの不均衡
12シャード均等割りだと最速2,388秒・最遅5,860秒（**2.5倍差**）で、遅いシャードに全体が
引きずられる。本番は**シャード数を増やす**か**行をシャッフルして割り当てる**と2〜3割縮む。

## 4-bis. 基準を触れないようにした仕組み（2026-08-15 本人指示「絶対に上書きするな」への対応）

1. **`server_sde/_baseline_guard.sh`** を新設し、`abl_labels.sbatch` と `abl_train.sbatch` の
   両方に組み込んだ。ジョブ冒頭で基準の指紋を記録し、末尾で照合して**1バイトでも違えば
   ジョブを失敗させる**。守る対象＝基準3データセット・基準datasetsルート・基準run・初期重みckpt
2. **`ABL_FULLVAL` フラグ**（既定0）を追加。学習ジョブで**唯一**基準ルートを参照する工程が
   「フル物理val推論」なので、確認runでは既定でスキップし自条件valのみ実行する。
   → 確認runは基準ルートに**読み書きとも一切アクセスしない**
   → **本番は `ABL_FULLVAL=1` が必須**（主要評価がこれ）
3. 書き込み先はこの3つのみ。ロールバックは削除するだけ:
   `out/dataset_outdoor_siren_v12_abl_<arm>/` /
   `PSELDNets/datasets_v12_abl_<arm>/` /
   `PSELDNets_logs/outdoor_siren_v12/runs/outdoor_siren_v12_abl_<arm>*`

### 得られた数値（**卒論・発表に使わない。比較不能**）

1. 評価セットが違う（こちらはval、確定値はfold20の確定評価セット）

3. 自条件val＝「その世界で学習しその世界で採点」であり、**主要評価のフル物理val
   （転移ギャップ）ではない**（確認runでは基準ルートに触れないため意図的に切った）

→ armの良し悪しはこの数値からは**何も言えない**。本番で §9.3 の主要評価を測ること。

**ラン揺れフロア** = 基準と完全同一条件・seedのみ変更（job834）で測定した run 間のブレ。
§9.3の事前登録どおり「**フロア以下の差は差なし**」と判定する。

### 効き目の順位

**地面反射 > 幾何減衰 > ドップラー ≫ 大気吸収（効果なし）**

### 事前登録（§9.4）との答え合わせ

| arm | 予想 | 実測 | 判定 |
| --- | --- | --- | --- |
| no_airabs | **差なし**（≲50mでは高々1-1.5dB） | 全指標フロア内 | **的中** |
| no_1r | 最大の差 | −8.1pt（2位） | 方向は的中・順位は外れ |
| no_doppler | 微差（\|ΔSELD\|≤0.005） | −3.3pt（フロアの3倍） | **やや外れ**（微差でなく有意差） |
| no_ground | el系はむしろ**改善** | **−10.9ptで最大の劣化** | **外れ** |

**外れた2つが研究上の中身**になる。特に地面反射は「仰角バイアスを生むだけ」と予想していたが、
実際は距離推定の手がかりとして効いていた可能性が高い（至近中央誤差が0.25→0.37mへ悪化）。

### 確認runとしての結論: **この実験デザインは信号を取れる**

差が出るarmと出ないarmが分かれ、しかも**「出ない」と事前に予想した条件（大気吸収）が
実際に出なかった**。4本とも大差が出れば計器の故障を疑うべきで、4本ともフロア内なら
スイッチ無効を疑うべきところ、そのどちらでもない。**計器に感度と特異度の両方がある**
ことの実証であり、本番を回す価値があると判断できる。
