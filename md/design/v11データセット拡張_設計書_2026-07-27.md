## 1. 学習 core の拡張（規模と構成）

### 1.1 規模の根拠
- 現状 v10 core = 10h（TAU-NIGENS 2021 と一致）。
- 次の土台 = **DCASE 2023 公式合成 20h** に合わせる（合成学習の標準スケール、引用可）。
- → **v11 core = 7,200本（10s×7200 = 20h）**、split = 4:1:1（TAU比）
  = **fold1 4800 / fold2 1200 / fold3 1200**。

### 1.2 co-occurrence 再設計（本丸）※方針=自然頻度寄せ＋重要セルのフロア（本人決定 2026-07-27）
現状の穴＝「学習が (車0,警告≥1) と 複数車 を見ていない」。
**素直な自然頻度だと稀セル（警告のみ・複数車・静穏）がまた薄くなり穴が残る**ため、
「**分布の形は自然頻度、ただし重要セルに絶対本数の下限（フロア）を保証**」する。
20h規模なら稀セルでも絶対数を確保できるのがこの両立の鍵。

**(1) 車の台数はシーン種別から自然に決める**（これが「自然頻度」の骨）:

| シーン種別 | 割合 | 車の台数の傾向 |
| --- | --- | --- |
| 静かな住宅街 | 40% | 0〜1台中心 |
| 中程度の生活道路 | 40% | 1〜2台中心 |
| 幹線道路沿い | 20% | 2〜3台中心 |

→ 結果として n_car の周辺分布は概ね {0:〜18%, 1:〜47%, 2:〜23%, 3:〜12%}（自然な裾）。

**(2) 警告音は検出対象なので必然的にオーバーサンプル**（真の出現率より高い）:
- n_warn 目標 {0:45%, 1:40%, 2:15%}。
- ※「警告音は現実の base rate より多い」ことは**設計上の意図的バイアスとして卒論に明記**
  （検出器の学習に必要。自然頻度に厳密に従うと学習例が枯れる）。

**(3) 重要セルの下限（フロア）を保証**（自然頻度で薄くなっても割り込ませない）:

| 重要セル | 最低本数 | 理由 |
| --- | --- | --- |
| 警告のみ・車なし (car0,warn≥1) | **≥400** | 「警告＝車」誤連想の根治（現状0） |
| 純静穏 (car0,warn0) | **≥300** | 幻覚フロア（現状20→桁違い強化） |
| 複数車 (car≥2) | **≥1500合計** | 同時定位62.5%頭打ちの打破（現状core0） |

制約:
- クラス×危険層×側の均衡（既存 build_core/check_core を流用、許容差は sqrt(規模)で自動スケール）。
- 「警告のみ・車なし」クリップに危険層は付かない（車が無いので tier=na）。
  → 割当表スキーマに n_car 列を追加、danger_tier は車がある行のみ。
- 複数車は v10a の track 機構（既存 build_v10a）を core に統合。
- **学習=自然頻度＋フロア／評価の現実準拠セット(§2.2)も自然分布**で train/eval を整合させ、
  claim-critical セット(幻覚600・safe600)だけは非自然（全車なし等）のストレス試験とする。

### 1.3 実装メモ（Fable向け）
- step10_v11_plan.py: build_core を n_car グリッド対応に拡張（後方互換で既定=v10挙動）。
- step11_v11_render.py: v10レンダラを import、n_car・警告のみ経路を追加。
- 決定論チェック（同一seedで2回生成のmd5一致）と全数検算（precheck）は必須継続。

## 2. 評価セットの拡張（本数と新種）

### 2.1 既存セットの増量（claim-criticalに応じ段階化）
統計的強さの根拠（Wilson95%下限・誤検出0のPoisson95%上限）:
- n=20 → 100%の下限83.9% / 誤検出0で54回/時
- n=200 → 96.3% / 5.4回/時
- n=600 → 99.4% / 1.8回/時

| セット | 現 | v11目標 | 根拠 |
| --- | --- | --- | --- |
| 幻覚フロア（車なし×サイレン） | 50 | **600** | 主張の要。0件で「1.8回/時以下」まで言える |
| safe層の過剰通知抑制 | (core内) | **専用600** | 実用性の要（過剰通知72.5%が弱点） |
| S1 警報マスク下の車 | 20 | **200** | マスキング頑健性 |
| 複数車 同時定位（v10a） | 60 | **200** | 62.5%頭打ちの検証力を上げる |
| S5 悪条件サイレン | 20 | **200** | 検出限界 |
| その他S2/S3・プローブ・交差点 | 20〜48 | **100** | 補助 |

### 2.2 新種の現実準拠シナリオ（DHH優先度・道路安全に基づく）
根拠: Findlater et al. CHI2019（DHH N=201、緊急音>人>家電の優先度）／道路安全資料。
各 n≈100〜200 で追加:

| # | シナリオ | 狙う現実の失敗モード | 物理で表現可能か |
| --- | --- | --- | --- |
| N1 | 見通し不良の交差点で右左折車 | 遮蔽→急に現れる接近車 | 可（軌道で近接開始） |
| N2 | 後方からの静音車/EV（AVAS下限） | 50-56dB@2mの最も拾いにくい車 | 可（音量下限＋既存tire/eng） |
| N3 | 駐車場：複数バック車＋反響 | バック音の同方向多重 | 可（S3拡張＋track） |
| N4 | 緊急車両の遠近通過（ドップラー最大） | 高速接近のリードタイム | 可（速度上限） |
| N5 | 繁華街：多数の妨害音源 | 多重同時での分離 | 可（警告2＋車3＋暗騒音上限） |
| N6 | 自転車/キックボードの真横〜後方追い越し | 視覚の効かない方向 | 可（S2拡張） |
| N7 | 停車車両の発進（0→加速） | 静→動の立ち上がり | 可（軌道で加速近似） |

**保留（物理未対応、限界として明記）**: 雨天・強風（暗騒音のスペクトル変化と風雑音は
現行の拡散ピンク雑音では非現実。v12以降 or 実録で対応）。

## 4. 実録評価アンカー（外部妥当性）

### 4.1 目的と規模
- 目的: 学習ではなく**評価のみ**。「合成で学んだモデルが実音でも動く」の一点。
- 規模の根拠: STARSS23 test=78本。FOAマイク実録は手作業で高コストのため
  **30〜60本**で「smoke test（煙感知＝致命的破綻の有無）」とする。数千本は不要。

### 4.2 条件（各10本前後）
| 条件 | 内容 |
| --- | --- |
| C1 静かな生活道路 | 単一接近車・低暗騒音 |
| C2 交通量のある道路沿い | 複数車・高暗騒音 |
| C3 サイレン通過 | 実救急/消防のドップラー |
| C4 踏切/警報 | 実踏切音＋接近車があれば理想 |

### 4.3 パイプライン（既存を使う）
- 収録: FOAマイク（ACN/SN3D）＋騒音計でLAeq同時記録（絶対較正の錨）。
- step19_realsmoke_convert.py: 暗騒音区間のA特性を騒音計読みに合わせ絶対較正。
- step20_realsmoke_score.py: 通知層で採点（リードタイム・誤通知）。
- 注意: 実録はラベルが人手→方向は粗くてよい（検出/リードタイム中心に評価）。

## 4.5 デコーダ閾値掃引実験（threshold_unify）— 複数車62.5%頭打ちの切り分け
2026-07-27 のローカル診断で、複数車の取りこぼしが**角度の近さと強く相関**すると判明:
- v10a で真に車2台のフレーム4,765を分析。**両方報告=真の方位差 中央118.5°（<15°は4.8%）／
  片方落ち=中央9.0°（<15°が65.4%）**。→ 近接2台の取りこぼしが頭打ちの主因候補。
- ただし片方落ちの**35%は>15°離れている**（統合では説明不可＝マスキングorモデル側要因）。

**仮説**: 62.5%頭打ちは学習の限界でなく **decoder の threshold_unify=15°**（PSELDNets
`src/utils/data_utilities.py:302 multi_accdoa_to_dcase_format`）が主因の可能性。
**注意**: 予測CSVは統合済み＝閾値変更には**統合前のトラック別生予測が必要**（再推論が要る）。

設計（凍結ポリシー上=評価/デコーダ層で自由）:
1. 推論セルを改造し、**統合前のトラック別イベント**（3トラックの sed/doa）を保存。
2. threshold_unify を **5/10/15/20° で掃引**（ローカル、再推論不要でこの部分は回せる）。
3. 各閾値で **同時検出率↑ vs 幻検出/重複↑** のトレードオフを測り膝を出す。
   - threshold_unify は「1台を2トラックが重複検出したのを畳む」安全装置＝下げると
     precision低下（幻検出増）の副作用。単純に下げず最適点を測る。
4. **pin済みsubmoduleは編集せず**、threshold_unify を推論/採点ラッパーから引数で渡す。
5. 結論の二分: 下げて回復→「頭打ちはデコーダ設計が主因」／回復せず→「モデルの分離限界」。
   どちらでも卒論の知見（unify 15°の「等」を実測で確定）。
